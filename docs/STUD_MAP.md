# Шпильки → «Визуализация»: 3D-карта дефектов шпилек

Страница `/studs/map` — третья вкладка «Визуализация» раздела «Шпильки» (после «Записать» и
«Журнал»): 3D-кузов и схемы
моделей A13T / A01 / P01 / CS55p с точками дефектных шпилек, разбивка по видам дефектов
и станциям, тренд по неделям.

## Что где лежит

| Что | Где | В git? |
|-----|-----|--------|
| Код карты (JS, шрифты, index.html) | `app/static/stud-map/` | да |
| Маршруты, загрузка реестра | `app/blueprints/stud_map.py`, `app/stud_map_data.py` | да |
| Схемы (чертежи OEM): `body/`, `img/`, `parts/`, `body.json`, `views.json` | `data/stud_map/` на сервере | **нет** |
| Данные реестра `defects.json`, последний `register.xlsx` | `data/stud_map/` на сервере | **нет** |

Репозиторий публичный — чертежи и реестр цеха в него не кладём (`.gitignore`: `data/stud_map/`).
Все файлы карты отдаются только вошедшим пользователям (общий щит входа).

## Вид и тема

- Модель выбирают в плашке слева вверху (нажать на «Chery A13T» → список моделей с числом дефектов);
  отдельного блока «Модель» внизу нет.
- Цвета — как у сайта: тёмная или светлая тема (переключатель ☀/🌙 в шапке), карта меняется сразу.
  Светлая — исходная «бумажная» палитра карты, тёмная — цвета сайта. Рисунки схем остаются светлыми.
- «Категория дефекта» фильтрует всю аналитику: сводку, «Виды дефектов», «Станции», числа у недель
  и моделей, 3D и график. Кнопка «Все» — все категории; при «Все» нажатие на категорию оставляет
  только её, дальше нажатия добавляют/убирают; если убрать последнюю — снова «Все».
- Компактная панель: кнопки «Весь кузов / станции» у «Видов дефектов» и ещё 2 показателя сводки —
  за «⋯»; «Все шпильки вида» (бледные недефектные шпильки) — в меню «⋯» карты → «Показать»,
  по умолчанию выключено; список дефектных шпилек — широкий в несколько колонок, карточка шпильки под ним.
- «Во весь экран»: где браузер умеет (компьютер, Android) — настоящий полноэкранный режим; на iPhone
  (Safari разворачивает только видео) окно карты растягивается на весь экран поверх шапки сайта.
- Режим **«Запись»** (кнопка справа от модели; обратно — «Дефекты»): все шпильки с номерами, без
  дефектов и аналитики — для оператора. Два вида: **3D** — та же сцена, что у дефектов (второго 3D нет:
  флажок `window.__smRec` в сборке показывает все шпильки обычным видом с номерами, каждая нажимается →
  карточка: номер, тип, картинка, на каких А-листах, «Записать дефект»); **А-лист** — чертежи цеха с
  напечатанными номерами: вкладки, масштаб (кнопки, щипок, двойной клик), поиск по номеру, нажатие на номер.
  «Записать дефект» пока неактивна: куда записывать — решается; подключение — `window.__smRecordStud =
  ({model, no, part}) => …`. Код режима — `app/static/stud-map/layout.js` (обычный JS; поменяли — поднять `?v=`).
- `app.*.js` — собранный файл (three.js r147, MIT, + код карты), исходников в репозитории нет.
  Правки в нём: фон 3D-сцены из `window.__smBg` (тема сайта); категории учитываются в сводке,
  «Видах дефектов», «Станциях», счётчиках недель и моделей; кнопка «Все» в категориях;
  «все шпильки вида» по умолчанию выключено; режим «Запись» (`window.__smRec`): все шпильки обычным видом
  с номерами (видны и в обзоре — наложенные прячутся, при приближении появляются остальные), без плашек «без №»,
  нажатие → `window.__smPick`; `window.__smRedraw` — перерисовка снаружи.
  Шпильки всех марок — одним золотистым цветом `#D4780E` (раньше у GWM/Changan были белые «стальные»);
  всплывающие подсказки у кнопок станций (FF, RF… «нажмите ещё раз — снизу») убраны, повторное нажатие
  по-прежнему переключает вид.
  После любой правки сборки файл переименовывают (`app.<хеш>.js` + `.gz`) и меняют ссылку в
  `index.html`: браузеры кешируют его на год.

## Установка на сервер (один раз)

1. Обновить код: `deploy\update.ps1` (подтянет ветку, поставит `openpyxl`, перезапустит службу).
2. Распаковать архив схем в `C:\WeldTeam\data\stud_map\` — внутри должны быть
   `body\`, `img\`, `parts\`, `body.json`, `views.json`.
3. Открыть «Шпильки» → «Визуализация» → **Загрузить реестр (xlsx)** (справа над картой) → выбрать
   `Stud_Defect_Register_BS_rev….xlsx`.

## Обновление данных

Кнопка **↻ Обновить реестр** справа над картой (до первой загрузки — «Загрузить реестр (xlsx)»;
видна только отделу WeldTeam и админу, в подсказке — какой файл сейчас на карте): сервер читает лист
«Реестр дефектов» (+ выпуск из «WEEKLY ANALYSIS» и «Graphs») и сразу пересчитывает карту.

Без сайта, на сервере:

```powershell
cd C:\WeldTeam
.venv\Scripts\python scripts\stud_map_update.py "D:\путь\Stud_Defect_Register_BS_rev12.xlsx"
```

## Права

Смотреть — все отделы, у которых есть раздел «Шпильки» (`app/permissions.py`: blueprint `stud_map` →
`studs`). Загружать реестр — WeldTeam и админ (проверяет сам эндпоинт).

## 3D-форма пола

Пол в режиме «Кузов» — условная 3D-форма: положения типовых элементов днища (передний и задний пол на одном уровне; тоннель,
поперечины, пороги, ниша запаски, подъём к щиту) сняты со схем каждой модели, рисунки схем лежат на
этой форме, шпильки пола стоят на поверхности. Глубины условные (±3–5 см) — в схемах цеха их нет.
Точная форма — по STL/CAD (тогда же можно поставить точки по координатам X/Y/Z).

## Категории

Категория реестра «Склейка / Stick Weld (SW)» на карте — «Непровар (SW)» (это непровар): шпильки
на месте нет, остаётся чёрный нагар с брызгами. Остальные — как в реестре.

Шпильки на 3D-кузове крупнее настоящих, поэтому стоящие ближе 7,5 см (на одной стороне панели)
раздвигаются по поверхности, чтобы в одном месте не было двух шпилек; в подсказке написано,
с какой шпилькой раздвинута и сколько между ними на схеме. Номерки не налезают друг на друга:
если два номерка перекрываются, виден у шпильки с бо́льшим числом дефектов (у выбранной — всегда).

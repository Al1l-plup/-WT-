# Как работать с проектом в Git

Короткая инструкция по совместной разработке WeldTeam MES.

## Ветки

| Ветка | Назначение |
|-------|------------|
| `main` / `master` | Стабильные релизы. Прямые коммиты **запрещены**. |
| `dev` | Основная рабочая ветка. Сюда вливаются готовые фичи. |
| `feature/*`, `fix/*` | Ветки под конкретную задачу, создаются **от `dev`**. |

Прямо в `main`/`master` не коммитим — только через Pull Request из `dev`.

## Типовой рабочий цикл

```bash
# 1. Обновить dev
git checkout dev
git pull origin dev

# 2. Создать ветку под задачу
git checkout -b feature/kratkoe-opisanie      # или fix/opisanie-baga

# 3. Работать, коммитить небольшими логическими порциями
git add <файлы>
git commit -m "feat: добавил экспорт дефектов в CSV"

# 4. Отправить ветку и открыть Pull Request в dev
git push -u origin feature/kratkoe-opisanie
```

После ревью и вливания в `dev` ветку задачи можно удалить.

## Формат сообщений коммитов

Используем [Conventional Commits](https://www.conventionalcommits.org/):

```
<тип>: <краткое описание в повелительном наклонении>
```

Основные типы:

- `feat:` — новая функциональность
- `fix:` — исправление бага
- `refactor:` — изменение кода без изменения поведения
- `docs:` — документация
- `test:` — тесты
- `chore:` / `build:` — рутина, зависимости, структура

Примеры: `feat: планирование ТО на квартал`, `fix: неверный расчёт среднего тока`.

## Перед коммитом

```bash
pytest            # тесты должны проходить
ruff check .      # проверка стиля (по желанию)
```

Не коммитьте: `.venv/`, `.env`, `__pycache__/`, служебные файлы SQLite
(`*.db-wal`, `*.db-shm`, `*.db-journal`) — они уже в `.gitignore`.

## Изменения в схеме БД

Схема правится **только** через `app/migrations.py` — добавляйте новый
идемпотентный шаг (обёрнутый в try/except или `IF NOT EXISTS`), чтобы миграция
безопасно применялась к существующей базе. Не редактируйте структуру вручную в БД.

Сам файл `data/welding_shop.db` коммитится в репозиторий. Если вы наполнили его
новыми данными и хотите поделиться — коммитьте базу отдельным коммитом
(`chore: обновил БД …`), чтобы изменения кода и данных не смешивались.

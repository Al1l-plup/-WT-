# WeldTeam MES — Карточка прогресса проекта

> **Обновлено:** 2026-07-23
> **Репозиторий:** [Al1l-plup/-WT-](https://github.com/Al1l-plup/-WT-) · рабочая ветка **`DEV`**
> **Запуск:** `python run.py` (разработка) / `python wsgi.py` (Waitress, прод) — порт 5000

Веб-приложение (MES) для цеха точечной сварки BS: бренды **Chery / GWM / Changan**.
Учёт ТО сварочных клещей, доска дефектов с рабочим процессом, аналитика, Обзор данных,
Excel-подобный редактор БД с журналом версий и полный инженерный Weld Balance.

---

## 1. Стек технологий

| Компонент | Решение |
|-----------|---------|
| Backend | Python 3.11+ · Flask 3 (app factory + blueprints) |
| WSGI (прод) | Waitress (кроссплатформенный, работает под Windows) |
| База данных | SQLite — `data/welding_shop.db` (в git **не хранится**) |
| Миграции | Alembic (`migrations/`), авто-`upgrade head` при старте |
| Конфигурация | `python-dotenv` (`.env`, профили dev/prod/testing) |
| Frontend | Серверные шаблоны Jinja2 + чистый CSS/JS (без сборки) |
| Excel-грид | `app/static/sheet.js` (виртуальный скролл, копипаст, undo/redo) |
| Тесты / линт | pytest + ruff, CI на GitHub Actions (`.github/workflows/`) |

## 2. Архитектура

```
app/
├── __init__.py          # create_app() — фабрика; before_request-щит аутентификации
├── config.py            # профили dev/prod/testing, чтение .env
├── db.py                # соединение SQLite через flask.g
├── migrations.py        # запуск Alembic upgrade head при старте
├── audit.py             # триггеры change_log, откат правки/пакета, точки восстановления
├── documents.py         # конфиг «документов» редактора + resolve_weld_point_links (связи)
├── snapshots.py         # заморозка контекста фактов (историческая целостность)
├── errors.py            # единая обработка ошибок API (без утечки деталей)
├── constants.py         # коды дефектов, список отделов
└── blueprints/          # pages, catalog, maintenance, defects, analytics,
                         # workers, explorer, admin, auth
migrations/versions/     # 0001…0008 (см. §4)
scripts/                 # init_db, dump_seed, import_weld_balance, sync_wb_links
tests/                   # 15 файлов, ~79 тестов (self-contained, см. §6)
docs/                    # BEST_PRACTICES, PROGRESS, DATA_MAP, …
```

Схема БД **read-heavy, версионируемая**: факты (ТО, дефекты) хранят `snap_*`-копии
контекста, чтобы история не «плыла» при переносе точек/клещей. Все правки редактора
фиксируются в `change_log` через SQLite-триггеры и откатываются пакетом.

## 5. Хронология вех (по коммитам)

| Этап | Итог |
|------|------|
| **Реструктуризация** | Монолит `temp_server` (1 файл на 1500 строк) → чистое Flask-приложение: app factory, blueprints, `.env`, зависимости, тесты |
| **Историческая целостность** | `snap_*`-колонки в ТО/дефектах — факты не «плывут» при изменении привязок |
| **Инфраструктура** | Alembic, БД вне git (сборка из миграций + seed), обработка ошибок, логирование, CI |
| **Weld Balance** | Импорт 5 файлов `.xlsm` в нормализованный слой (≈15 тыс. точек); 4 вкладки по моделям; показ ВСЕХ колонок Excel |
| **Редактор БД** | Excel-подобный грид (виртуальный скролл 16 тыс. строк, копипаст, undo/redo, порядок строк) + журнал версий с откатом пакета/к точке |
| **Аутентификация** | Регистрация/вход (обязателен на весь сайт), отдел ИТО, автор правок из сессии |
| **Валидация и переносы** | Уникальность G-номеров/точек, e-mail-логин; перенос гана (смена трансформатора) и точки (смена G) с сохранением истории |
| **WB = источник правды** | `model_code`, полная синхронизация связок с Обзором; наследование программы сварки при переносе точки туда-обратно |
| **Вставка из Excel** | Грид WB = зеркало листа «Welds» (53 колонки 1:1) — `Ctrl+V` из Excel ложится без сдвига; детали и служебные колонки пишутся через setters |
| **Мобильные + a11y** | Анти-зум iOS (16px), тач-цели ≥44px, safe-area iPhone, focus-visible, `theme-color`, `prefers-reduced-motion` |
| **Ролевой доступ (RBAC)** | Права по отделам (WeldTeam/ИТО/ОТК/Производство), щит `before_request` + гейт навигации; админ-панель `/users` (смена отдела, вкл/выкл, сброс пароля временным — без хранения открытых паролей) |
| **Актуализация оборудования** | `scripts/import_equipment.py` (dry-run/apply) сверяет БД с «Актуальным перечнем» Excel: цепочка G-номер → трансформатор → станция → бренд; добавляет новое, чинит типы клещей, переносит клещи на верные трансформаторы (без удалений) |
| **Развёртывание** | `deploy/install.ps1` — установка на Windows Server одной командой (Python/Git/код/venv/.env/служба NSSM с автозапуском и авто-перезапуском); гайд `docs/DEPLOY_WINDOWS.md` |
| **Аудит и надёжность** | Полный функциональный прогон (49 проверок, 0 сбоев); автор правок в журнале — из сессии для ВСЕХ вкладок (единый хук); включён контроль внешних ключей (удаление связанной записи блокируется) |

## 6. Тестирование

- **~79 тестов** в 15 файлах, все **self-contained**: эталонная БД собирается из
  миграций + `db/seed.sql` во временной папке — прогон воспроизводим в CI, не зависит
  от боевой БД.
- Покрыто: аутентификация, валидация ввода, переносы гана/точки, синхронизация
  связок WB↔Обзор, вставка из Excel (детали/raw_extra), неизменяемость истории,
  журнал/откат, натуральная сортировка, мобильная вёрстка и доступность.
- Запуск: `pytest -q` + `ruff check .` (оба зелёные на текущем `DEV`).

## 7. Известный техдолг (честно)

- **Нет базового Jinja-шаблона** — `<head>`, шапка и подключение скриптов
  продублированы в 10 файлах `app/templates/*.html`. Нужен `base.html` + `{% extends %}`.
  Пока от рассинхрона мета-тегов страхует `tests/test_mobile_a11y.py`.
- **UNIQUE-индексы `gun.g_num` и `spot(model_id, spot_number)` не наложены** — в данных
  есть исторические дубли (5 × G-номер, 1 × точка); индексы после ручной очистки.
- **Настоящего Weld Balance для CS55/CS65 нет** — присланные файлы оказались копиями
  A01/A13T (проверено построчно), исключены из импорта (`SKIP_FILES`). Вкладка CS55
  живёт на первоначальной загрузке до появления корректного файла от Changan.
- **Роль admin — по одной почте** (`ADMIN_EMAIL`). Полноценных ролей/групп прав пока нет —
  права жёстко привязаны к отделу (`app/permissions.py`). Если понадобится более гибкая
  модель (несколько админов, кастомные наборы прав) — вынести в таблицу ролей.
- **Сессия хранит отдел 30 дней** — при смене отдела пользователя админом права обновятся
  только после его повторного входа (для админа переэлевация — на каждом входе).
- **Excel-перечень оборудования внутренне неполон** — ~20 клещей ссылаются на
  трансформаторы, которых нет в списке трансформаторов того же файла (`GW-MB-100-W032-T3`;
  `GW-EC1-20` — станция без `-T`). `scripts/import_equipment.py` их пропускает (оставляет
  на текущем трансформаторе) — нужен исправленный файл.
- **Дубли `transID`** (`GW-INR L-10-T1`, `GW-INR R-10-T1` — по 2 записи) — историческое,
  не от синхронизации; ручная сверка перед UNIQUE-индексом.
- **«Участок/линия»** (Линия сборки кузова и т.п.) из Excel в БД не хранится — в редакторе
  «Линия» = бренд; отдельное поле участка — доработка схемы при необходимости.
